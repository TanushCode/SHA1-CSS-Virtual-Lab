Experiment Overview

Aim & Objectives

Study the fundamental mechanics of cryptographic hashing through the Secure Hash Algorithm 1 (SHA-1).

Experiment Title

SHA-1: Generate the SHA-1 hash value for a given input message and study its output characteristics and sensitivity to input changes.

Primary Aim

To implement, analyze, and simulate the 160-bit SHA-1 cryptographic hash algorithm, validating its deterministic properties, fixed output length, message compression pipeline, and the avalanche effect when input data undergoes slight mutations.

Educational Objectives

Understand the pre-processing padding scheme, 512-bit block partitioning, and 64-bit length appending.

2. Iterative Compression

3. Output Determinism

Generate exact 160-bit (40 hexadecimal characters) message digests across various message lengths.

4. Avalanche Effect Analysis

Quantify output bit variance (target ~50%) when a single character or bit in the input message is modified.

Cryptographic Principles

Theory: SHA-1 Hash Algorithm

The Secure Hash Algorithm 1 (SHA-1) is a cryptographic hash function designed by the United States National Security Agency (NSA) and published as a U.S. Federal Information Processing Standard (FIPS PUB 180-1) in 1995.

1. Essential Properties of Cryptographic Hash Functions

A secure cryptographic hash function takes an arbitrary-length message $M$ and produces a fixed-length digest $H(M)$. It must satisfy three core security properties:

  • Pre-image Resistance (One-Way): Given a digest $h$, it is computationally infeasible to find any message $m$ such that $H(m) = h$.
  • Second Pre-image Resistance (Weak Collision Resistance): Given an input $m_1$, it is computationally infeasible to find a different input $m_2 \neq m_1$ such that $H(m_1) = H(m_2)$.
  • Collision Resistance (Strong Collision Resistance): It is computationally infeasible to find any two distinct messages $m_1 \neq m_2$ such that $H(m_1) = H(m_2)$.

2. SHA-1 Algorithm Specifications

Parameter Specification
Digest Size (Output Length) 160 bits (20 bytes, represented as 40 hexadecimal characters)
Input Block Size 512 bits (16 words of 32 bits each)
Word Size 32 bits
Maximum Input Message Size $2^{64} - 1$ bits
Total Processing Rounds 80 rounds (organized into 4 logical stages of 20 rounds each)
Initial Register State Variables 5 registers: $A, B, C, D, E$ (each 32 bits, total 160 bits)

3. Step-by-Step Processing Pipeline

Step 1: Message Padding

The input message is padded so that its total bit length is congruent to 448 modulo 512 ($L \equiv 448 \pmod{512}$). Padding is always performed, even if the message already has the desired length.

1. Append a single '1' bit to the end of the message.
2. Append $k$ zero bits ('0'), where $k$ is the smallest non-negative integer satisfying:
    $(L + 1 + k) \equiv 448 \pmod{512}$

Step 2: Appending 64-Bit Length

A 64-bit unsigned integer representing the original message length $L$ (in bits) is appended to the padded message. This produces a complete padded message whose length is an exact multiple of 512 bits ($n \times 512$).

Step 3: Initializing Working Registers

A 160-bit buffer composed of five 32-bit registers $(A, B, C, D, E)$ is initialized with standard hexadecimal constants:

A = 0x67452301
B = 0xEFCDAB89
C = 0x98BADCFE
D = 0x10325476
E = 0xC3D2E1F0

Step 4: Message Schedule Expansion

Each 512-bit block is divided into sixteen 32-bit words $W_0, W_1, \dots, W_{15}$. These are expanded into eighty 32-bit words $W_{16}, \dots, W_{79}$ using bitwise XOR and circular left-shift:

For t = 16 to 79:
W[t] = ROTL^1 ( W[t-3] ⊕ W[t-8] ⊕ W[t-14] ⊕ W[t-16] )

Step 5: 80 Rounds of Iterative Compression

The 80 rounds are divided into 4 stages of 20 rounds each. Each stage uses a distinct non-linear logical function $f_t$ and additive constant $K_t$:

Stage Rounds ($t$) Non-linear Function $f_t(B, C, D)$ Constant $K_t$ (Hex)
Stage 1 0 – 19 $(B \land C) \lor (\neg B \land D)$ (Ch / Conditional) 0x5A827999
Stage 2 20 – 39 $B \oplus C \oplus D$ (Parity) 0x6ED9EBA1
Stage 3 40 – 59 $(B \land C) \lor (B \land D) \lor (C \land D)$ (Maj / Majority) 0x8F1BBCDC
Stage 4 60 – 79 $B \oplus C \oplus D$ (Parity) 0xCA62C1D6
For each round t from 0 to 79:
TEMP = ROTL^5(A) + f_t(B, C, D) + E + W_t + K_t
E = D
D = C
C = ROTL^30(B)
B = A
A = TEMP

Step 6: Producing the 160-Bit Digest

After all 80 rounds, the working registers are added modulo $2^{32}$ to the previous hash block chaining variables. The final output is formed by concatenating $A, B, C, D, E$ into a 40-character hexadecimal string.

4. The Avalanche Effect

A critical characteristic of any robust cryptographic hash function is the Avalanche Effect: a minute change in the input (such as flipping a single bit or changing a character case) causes an unpredictable and widespread change in the output digest.

Ideal Cryptographic Avalanche Target

Theoretically, in a well-designed hash function, changing 1 bit of the input should cause each bit of the output to flip with a probability of 0.5. Thus, approximately 50% (80 out of 160 bits) of the output digest should change.

5. Current Cryptanalytic Status

In 2005, researchers (Wang et al.) discovered theoretical collision vulnerabilities in SHA-1. In 2017, researchers from CWI Amsterdam and Google announced the SHAttered attack, generating the first real-world collision (two distinct PDF files producing the same SHA-1 hash). As a result, industry standards (NIST, IETF) have deprecated SHA-1 for digital signatures in favor of SHA-256 and SHA-3.

Real Laboratory Procedure

Choose an alphanumeric input string $M$. Convert each ASCII character into its 8-bit binary representation to compute the initial bit length $L$.

💡 Example: For the message abc, $L = 3 \times 8 = 24$ bits.

Append a single 1 bit, followed by enough 0 bits so that the total length satisfies $(L + 1 + k) \equiv 448 \pmod{512}$. Then append the original length $L$ as a 64-bit big-endian integer.

💡 Padding is always performed — even if the message is already the right length — to ensure the standard is consistently applied.

Initialize the 5 working registers $(A, B, C, D, E)$ with the standard SHA-1 IV constants. For each 512-bit block, execute all 80 rounds of compression, updating registers each round.

A=0x67452301   B=0xEFCDAB89   C=0x98BADCFE   D=0x10325476   E=0xC3D2E1F0

Introduce a minimal change in the original input — flipping a single bit, changing case, or swapping one character. Compute the new 160-bit SHA-1 digest for the mutated message.

💡 Even one character change should produce a completely different digest — this is the Avalanche Effect.

Convert both 40-character hex digests into 160-bit binary strings. XOR them bit-by-bit and count the differing positions. Compute the percentage:

Percentage Difference = (Changed Bits / 160) × 100%
🎯 A well-designed hash function should yield ~50% difference (~80 out of 160 bits changed).

Knowledge Verification

Assessment: SHA-1 Architecture Quiz

Test your understanding of SHA-1 architecture, processing pipeline, security properties, and cryptanalysis. 18 questions across 4 sections.

Section A — Hash Function Fundamentals

1. What is the output digest size of the SHA-1 algorithm?

Explanation: SHA-1 always outputs a 160-bit digest, displayed as 40 hexadecimal characters. This is fixed regardless of input length.

2. A cryptographic hash function must be deterministic. What does this mean?

Explanation: Determinism guarantees that hashing the same message always yields the identical digest, making verification reliable across all platforms and times.

3. Which property states it is computationally infeasible to find any input that maps to a given hash output?

Explanation: Pre-image resistance (one-way property) ensures that given only a hash $h$, you cannot efficiently find $m$ such that $H(m) = h$. This underpins password hashing security.

4. What is the maximum length of the input message that SHA-1 can process?

Explanation: The SHA-1 standard (FIPS 180-1) specifies a maximum message length of $2^{64} - 1$ bits. The 64-bit length field appended during padding encodes this value.

5. Which NIST standard originally published the SHA-1 specification?

Explanation: SHA-1 was standardised in FIPS PUB 180-1 (1995). FIPS 140-2 covers cryptographic module validation, FIPS 197 is AES, and RFC 2104 defines HMAC.
Section B — SHA-1 Processing Pipeline

6. During SHA-1 padding, the message is padded so its bit length is congruent to which value modulo 512?

Explanation: Padding makes the message length $\equiv 448 \pmod{512}$. The remaining 64 bits are used to encode the original message length, making the total a multiple of 512.

7. How many 32-bit working registers does SHA-1 use during its compression function?

Explanation: SHA-1 uses five 32-bit registers $A, B, C, D, E$ (total 160 bits). After all blocks are processed, these are concatenated to produce the final digest.

8. In SHA-1's message schedule, the 16 original 32-bit words $W_0$–$W_{15}$ are expanded to how many words?

Explanation: SHA-1 expands the 16 message words into 80 words using: $W_t = \text{ROTL}^1(W_{t-3} \oplus W_{t-8} \oplus W_{t-14} \oplus W_{t-16})$ for $t = 16$ to $79$.

9. The 80 compression rounds in SHA-1 are divided into how many stages?

Explanation: SHA-1 organises 80 rounds into 4 stages (rounds 0–19, 20–39, 40–59, 60–79), each using a distinct non-linear function $f_t$ and additive constant $K_t$.

10. What logical function does SHA-1 use during rounds 20–39 (Stage 2)?

Explanation: Stages 2 and 4 both use the Parity function $f_t(B, C, D) = B \oplus C \oplus D$. Stage 1 uses Ch (Conditional), and Stage 3 uses Maj (Majority).
Section C — Security Properties & Avalanche Effect

11. In an ideal hash function, approximately what fraction of output bits change when one input bit is flipped?

Explanation: The Strict Avalanche Criterion (SAC) requires each output bit to flip with probability 0.5 per input-bit change, yielding ~50% diffusion across all 160 output bits.

12. Second pre-image resistance ensures that given a message $m_1$, it is infeasible to find $m_2 \neq m_1$ such that:

Explanation: Second pre-image resistance prevents finding a different message that hashes to the same value as a specific known message. This is distinct from collision resistance, where both messages can be freely chosen.

13. Which of the following best describes strong collision resistance (collision resistance)?

Explanation: (Strong) Collision resistance: no adversary can efficiently find any pair $(m_1, m_2)$ with $m_1 \neq m_2$ and $H(m_1) = H(m_2)$. Both messages are freely chosen — this is harder to break than second pre-image resistance.

14. How many bits does SHA-1 add to represent the original message length at the end of the padded block?

Explanation: SHA-1 appends a 64-bit big-endian representation of the original message length in bits. Combined with the padding bits, this makes the total padded length a multiple of 512.
Section D — Cryptanalysis & Real-World Implications

15. Why has SHA-1 been deprecated for digital signatures by NIST and major CAs?

Explanation: Google and CWI Amsterdam (2017) published the SHAttered attack: two distinct PDF files with identical SHA-1 digests. This proves SHA-1 collision resistance is practically broken.

16. Who first published theoretical collision vulnerabilities in SHA-1 in 2005?

Explanation: Wang, Yin, and Yu published a landmark 2005 CRYPTO paper showing SHA-1 collisions could be found far more efficiently than the brute-force birthday-attack bound, accelerating its eventual deprecation.

17. Which algorithm is recommended by NIST as the primary replacement for SHA-1 in digital signatures?

Explanation: NIST recommends SHA-2 (primarily SHA-256 or SHA-384) and SHA-3 as replacements for SHA-1 in security-critical applications. MD5 is also deprecated.

18. SHA-1's constant $K_t = \texttt{0x5A827999}$ is used in which stage?

Explanation: $K_t = \texttt{0x5A827999}$ (which equals $\lfloor 2^{30} \sqrt{2} \rfloor$) is the additive constant for Stage 1 (rounds 0–19), which uses the Conditional (Ch) function.
